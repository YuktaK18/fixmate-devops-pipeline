1. Aim
To implement Agile estimation techniques by performing effort and sprint estimation using Story Points, Planning Poker and T-Shirt Sizing; prepare project schedules using Agile planning tools such as Jira/GitHub Projects; visualize timelines through Sprint Backlogs, Burndown Charts and Gantt Charts; and compare Agile estimation approaches with Function Point Analysis (FPA).
2. System Overview — Fixmate
Fixmate is a Home Service Management System that helps customers discover and book home services such as plumbing, electrical repair, appliance repair and cleaning. It can support customer registration, service search, booking, payment, service-provider assignment, booking tracking and administrative reports.
Problem addressed: Customers may find it difficult to locate trusted service providers, book a convenient time, track booking progress and manage payments. Service providers and administrators also need a structured way to manage service requests and bookings.
Scope used for this experiment
The examples assume a Fixmate application with customer-facing booking features and an administrator/provider management area. External payment and notification services are treated as integrations. Function counts, estimates and schedules below are educational examples, not measured results from a deployed system.
3. Theory
3.1 Agile Estimation
Agile estimation is an iterative way to estimate the relative effort, complexity, uncertainty and workload involved in completing software work. Estimates are refined as the team learns more about requirements and risks.
3.2 Story Points
Story Points are abstract, relative units used to estimate a user story. They do not directly represent hours. Teams commonly use Fibonacci-based values such as 1, 2, 3, 5, 8, 13 and 21 because uncertainty tends to grow as work becomes larger.
3.3 Planning Poker
Planning Poker is a consensus-based estimation technique. The Product Owner explains a user story; team members independently choose a card; all cards are revealed; differences are discussed; and the team votes again until it agrees on a reasonable estimate.
3.4 T-Shirt Sizing
T-Shirt Sizing is a quick, qualitative method that classifies work as XS, S, M, L, XL or XXL. It is useful during early planning when the team needs a rough comparison before assigning numerical Story Points.
3.5 Function Point Analysis (FPA)
Function Point Analysis estimates functional size by classifying user-visible functions into five types: External Inputs (EI), External Outputs (EO), External Inquiries (EQ), Internal Logical Files (ILF) and External Interface Files (EIF). Complexity is classified as low, average or high using the applicable counting rules.

Unadjusted Function Points (UFP) = sum of (function count × applicable complexity weight).
Complexity Adjustment Factor (CAF/VAF) = 0.65 + (0.01 × TDI), where TDI is the sum of ratings for the 14 General System Characteristics. Adjusted FP = UFP × CAF.
3.7 Effort Estimation
Effort (person-hours) = Adjusted FP × productivity rate (hours per FP). Project duration (months) = total person-hours ÷ (team size × productive working hours per person per month). These are planning approximations; actual productivity depends on project context.

T-Shirt Sizing is a qualitative, quick comparison. Story Points provide a numeric relative estimate useful for sprint planning. There is no universal conversion between a T-Shirt size and a specific Story Point value; the team should estimate each method independently.
11. Conclusion
This experiment demonstrates that T-Shirt Sizing and Planning Poker support relative estimation and collaborative decision-making, while Function Point Analysis estimates functional size using defined function categories and complexity weights. Function Points can be converted to an effort estimate when a productivity rate is available. Backlogs, sprint boards, burndown charts and Gantt timelines help teams organize work and communicate progress. For Fixmate, these techniques provide a structured way to plan features such as service search, booking, payment and tracking. Actual estimates should be validated by the project team and updated as requirements become clearer.
